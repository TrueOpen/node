# TrueOpen Node Documentation

This directory documents the node implementation. It does not define the
protocol: the normative contract lives in the `TrueOpen/monorepo` specification
documents, and the wire format lives in the `TrueOpen/wire` release this
repository pins.

## Authority Order

When two statements disagree, the higher one wins:

1. The `TrueOpen/monorepo` protocol and service-design documents
   (`keeper_api_contract.md`, `keeper_data_structure_contract.md`, the
   `10-protocol_specifications` tree, and the accepted ADRs).
2. The pinned wire release: the descriptor image and domain registry named in
   `wire/pin.json`. Exact field numbers, registered RPC methods and frozen hash
   preimages come from there, never from a table written by hand.
3. This repository's own documents, for how the implementation realises the
   above.

A document here never authorises new consensus behaviour. It cannot allocate a
wire field, redefine a hash preimage, or enable a rule the protocol blocks.

## Contents

| Path | Purpose |
|---|---|
| `rpc.md` | Public RPC surface: transports, endpoints, pagination, hash encoding, errors. |
| `static/node-api.md` | Generated reference for every registered Msg and Query RPC. |
| `static/openapi.json` | Generated REST/OpenAPI surface. |
| `runbooks/` | Operator-facing procedures. |
| `templates/` | PR templates that gate contract-affecting changes. |

`static/` is generated by `make proto-gen` from the pinned descriptor. Do not
edit either file by hand; a change there that generation does not reproduce is
caught by `make proto-event-check`.
